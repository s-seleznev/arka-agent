## Опубликованная версия — 06.09.2026

Приложение называется **Арка**. Аркаша — ассистент внутри приложения. Техническое имя проекта Vercel `arkasha-agent` сохранено; клиенту передаём адрес выше.

Production deployment: `dpl_HtWw1q5gY8NW2ykx8wdf6md2E3kh`, статус READY. Публичный адрес проверен без входа в Vercel: HTTP 200, заголовок страницы «Арка».

При первом открытии создаётся гостевая сессия с четырьмя отчётами: проверка стельности, запуск в сухостой, контроль новотельных и животные на протоколах. Открывается пространство ассистента с чатом и таблицей. Чаты принадлежат конкретной гостевой сессии; чужие чаты не становятся общими.

## Модель и данные

- Vercel Hobby с Fluid Compute; модель — OpenRouter `openrouter/free`. Платные модели и переход на платный Gateway в этом режиме запрещены кодом.
- Neon Free хранит продуктовые таблицы и одну опубликованную синтетическую ферму в общей БД. `POSTGRES_URL` и `FARM_DATABASE_URL` указывают на неё; локальные базы остаются отдельными.
- В облачной ферме 170 записей животных и 3 483 события. Остальные локальные фермы и личные чаты в облако не копировались.
- Доступ гостя ограничен опубликованной фермой через `farm_access`, активную ферму и серверные проверки. Флаг `publicDemo` применяется только к синтетическому набору.
- Ключ модели, строка подключения, Auth.js secret и токен Blob хранятся в переменных окружения, не в Git. `DEMO_WELCOME_ENABLED=1` включает стартовые отчёты; `DEMO_PUBLIC_FARM_ID` должен совпадать с `FARM_ACTIVE_ID`.

## Исправление сбоя агента

Запрос «Кого нужно проверить на стельность?» обрывался с `Task timed out after 60 seconds`. Интеграционный тест также выявил двойное JSON-кодирование: модель передавала `filters` строкой вместо объекта, получала ошибку схемы и повторяла вызов.

Исправления:

- Максимум функции увеличен до 300 секунд. SDK ограничивает весь ответ 240 секундами, шаг — 90, отсутствие новых частей потока — 60, инструмент — 30. Автоматические сетевые повторы SDK отключены.
- `repairTableToolCall` распаковывает JSON-строки только в структурных аргументах `configureAnimalTable`, затем проверяет их исходной строгой схемой. Неверные поля, значения и попытки сменить ферму не исправляются догадками.
- После чтения скилла доступны настройка таблицы и уточнение контекста/скилла; после успешной проверенной настройки — только ответ. Это сокращает контекст и лишние шаги, не принуждая модель менять таблицу после информационного вопроса.
- Название чата формируется из текста запроса без отдельного обращения к модели.
- В чате остаётся сообщение об ошибке с кнопкой повтора. Повтор не вставляет тот же пользовательский message ID в БД второй раз.
- Логи содержат время подготовки, шаги, длительность инструментов и признаки ошибок, без секретов и содержимого пользовательских файлов.

## Что проверено

| Проверка | Результат |
|---|---|
| TypeScript и production-сборка | Прошли |
| Зависшая модель | SDK завершает поток по тайм-ауту |
| Двойное JSON-кодирование | Исправляется внутри одного вызова модели; инструмент выполняется один раз |
| Неверный JSON, лишние поля, чужой инструмент, смена фермы | Не обходят валидацию и ограничение фермы |
| Живой OpenRouter + облачная БД, отдельный тестовый чат | 20 животных; группы 4 / 4 / 12; правильные условия и колонки |
| Время этого прогона | 43,933 с до конца ответа; 49,558 с с независимой проверкой таблицы |
| Публичная страница | HTTP 200 |

Ранее в этой диагностике корректная выдача с лишними попытками заняла 148,877 с до конца ответа и 156,225 с с проверкой. Это единичные прогоны бесплатного маршрутизатора, не SLA и не доказательство стабильной задержки. Старые измерения локального Codex runtime к OpenRouter не относятся.

**Ограничение:** прямой автоматический POST к публичному `/api/chat` блокирует BotID (403). Защита не отключалась. Живая проверка модели и БД выполнена отдельным интеграционным скриптом; полный браузерный путь после исправления не подтверждён. Перед показом клиенту нужно повторить вопрос в браузере и проверить таблицу.

## Повтор проверки и публикация

`agent-app/scripts/openrouter-agent-smoke.ts` требует `AI_RUNTIME=openrouter`, серверные переменные окружения и `SMOKE_USER_ID` отдельного гостя, прошедшего штатный `/api/demo-workspace`. Скрипт использует реальную модель, создаёт собственный тестовый чат, проверяет таблицу и удаляет этот чат. Не использовать ID клиента. Запуск из `agent-app/` с уже заданным окружением:

```bash
node --conditions=react-server --import tsx scripts/openrouter-agent-smoke.ts
```

После разрешённой публикации обязательно назначать публичный alias новой READY-сборке и проверять адрес: технический адрес production сам по себе не доказывает обновление клиентской ссылки.

```bash
vercel deploy --prod --yes --scope <vercel-scope>
vercel alias set <ready-deployment-url> arka-agent-demo-2026.vercel.app --scope <vercel-scope>
```
