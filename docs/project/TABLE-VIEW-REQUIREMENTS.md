# Требования к таблице животных

## Уточнения текущей реализации — 05.09.2026

Выбранная ферма ограничивается сервером. Удаление условия «Ферма» из пользовательского фильтра не расширяет права и область активной фермы. Ранний контракт съёмного чипа ниже не является способом сменить серверную область.

CSV и печать выгружают всю выборку, а не viewport. CSV: до 100 000 строк и 25 MiB; печать: до 10 000 строк и 25 MiB. При превышении лимита или устаревшей ревизии — явная ошибка без частичного файла. Печать альбомная, заголовки повторяются, широкие таблицы разбиваются на блоки колонок с повтором номера животного. Визуальная приёмка шаблона не выполнена.


> Рабочий документ. [Навигация и актуальный срез](README.md). Датированные разделы описывают свой этап; ранние планы не подтверждают текущую готовность. Пути в командах указаны от корня репозитория.

## Актуальные уточнения интерфейса — 05.09.2026

Этот раздел имеет приоритет над прежними визуальными решениями ниже; версия модели представления v6 не меняется.

- Правая область: белый фон чата и таблицы. Боковое меню — `#FAFAFB`; верхняя панель — `--bg-topbar`, смесь 25% бокового фона и 75% белого в sRGB (после округления `#FEFEFE`). Заголовки столбцов — `--bg-table-section: #F9F9FA`.
- Нижняя панель имеет высоту верхнего меню — 46 px; сверху проходит непрерывная линия. Счётчик слева, действия «Скачать CSV» и «Напечатать» справа.
- Разделители меню, чата, таблицы и её нижней панели: 1 px, `--divider-color`. Обводки поля сообщения и карточек рекомендаций используют тот же цвет; оранжевая рамка поля сообщения при фокусе убрана.
- Кнопка открытия/закрытия таблицы закреплена справа на экране и не перемещается вместе с границей чата.
- Строка группы белая. Заголовок имеет вид «Атрибут: значение», пустое значение — «Не указано»; счётчик в плашке сразу после текста. Строка занимает ширину таблицы, не ограничивается первой колонкой.
- Группы раскрываются по умолчанию. Явно свёрнутые пути сохраняются в браузере отдельно по `viewId`; обновление ревизии не сбрасывает выбор пользователя. Синхронизации этого состояния между устройствами нет.
- При прокрутке текущая группа закрепляется под заголовками столбцов до вытеснения следующей. Заголовки и строки групп не должны выделяться как обычные ячейки; сворачивание остаётся доступным.
- В заголовке колонки многоточие появляется только при наведении. Кнопка использует `icon-xs` / `ghost`, как кнопка раскрытия карточки в номере. Меню содержит только «Скрыть колонку». У обязательного «Номера» многоточия нет. Скрытие столбца не отменяет группировку по его атрибуту.
- Кнопка фильтра не сохраняет нажатую заливку; счётчик сохраняет непрозрачный фон `--neutral-50` (#edeef1). Меню множественных значений и колонок немодальные. Поведение всех остальных выпадающих компонентов требует отдельной проверки.
- В переключателе фермы указан «Лактис Прайм 8». Контролы `farmId` скрыты из таблицы; это не устанавливает автоматически фильтр фермы в сохранённом запросе.

Статус: изменения внесены в код; итоговая ручная проверка прокрутки, закрепления, меню и восстановления состояния не завершена.

Статус: контракт Table View v6 зафиксирован 04.09.2026: дерево фильтров, один уровень группировки, единая высота верхних панелей `46 px`, сложенное боковое меню `46 px` и нейтральные разделители. Связанные документы: [исследование UX](FILTER-UX.md) | [интеграция агента и данных](AGENT-DATA-UI.md) | [план](PLAN.md).

## Дополнение v6 — исполнение правил CSV

Дерево, строка чипов, один уровень группировки и размеры оболочки сохранены. V1–v5 мигрируют в v6; исходное дерево v5 не упрощается. Исторические разделы о восстановлении v5 ниже описывают предыдущий этап.

- Пределы: 128 условий, глубина 8, 64 колонки; большой список применяется целиком, а не пакетом обрезанных операций.
- Новые значения: точное десятичное число без потери разрядов, сравнение с совместимым полем и дата относительно текущего дня фермы. Редактирование находится в прежнем popover условия.
- Обычное сравнение с отсутствующим значением не даёт совпадения, в том числе под НЕ. Для отсутствия используются отдельные операторы «пусто / не пусто».
- `ruleContext` хранит версию правила, привязку фермы, параметры, время и снимок данных. Ручная правка ставит `modified=true`, сохраняя происхождение.
- Устаревший снимок обновляется через существующий повтор загрузки или `refreshView`; ручные фильтры не заменяются исходным пресетом.

Реальная степень покрытия и незакрытые критерии: [rules/implementation-status.md](../../rules/implementation-status.md).

## 1. Результат

Пользователь управляет одной и той же выборкой животных вручную и через Аркашу. В правой панели постоянно видны четыре действия — **Фильтр**, **Сортировка**, **Группировка**, **Колонки**. **Фильтр** только показывает или скрывает отдельную строку активных фильтров; создание начинается кнопкой **Добавить фильтр** внутри этой строки. Все правила исполняются сервером по полной доступной выборке, таблица получает данные страницами, а агент работает с каноническим состоянием представления, а не с DOM или текстом контролов.

Отдельного расширенного режима нет. Каждый чип задаёт `атрибут → оператор → значение`, а каноническое состояние сохраняет дерево групп **И / ИЛИ / НЕ**. Простая формула выглядит как ряд чипов; вложенная формула показывается теми же чипами с текстовыми операторами и скобками.

Группировка использует не более одного атрибута: таблица показывает группы и сразу животных внутри выбранной группы. Для другого среза пользователь меняет поле группировки или добавляет фильтр.

## 2. Границы

В этот этап входят:

- новый интерфейс фильтрации, сортировки и группировки;
- согласованные изменения каркаса чата, бокового меню и разделителей панелей;
- `ReportView v5`, миграция сохранённых представлений и операции по стабильным ID;
- серверная фильтрация, сортировка, группировка и cursor-пагинация;
- автоматическая загрузка страниц с доступной кнопкой **Загрузить ещё**;
- точный контекст viewport и раскрытых групп для агента;
- двусторонняя синхронизация ручных и агентных изменений;
- проверки логики, доступа, доступности и масштаба.

Не входят изменение фактов фермы, произвольный SQL от модели, новый тип отчёта, переработка документов или содержимого карточки животного.

## 3. Неизменяемые правила

| Правило | Контракт |
|---|---|
| Основной объект строки | Животное; основной переход в карточку — его номер |
| Источник фактов | `arka_test` и проекция `animal_state_query` |
| Состояние отчёта | `ReportView` в продуктовой базе; оно не копирует и не меняет факты фермы |
| Доступ | Пользователь и агент работают только с фермами из `farm_access`; отсутствие фильтра **Ферма** означает все доступные фермы |
| Исполнение | Фильтр, сортировка и группировка применяются сервером ко всей выборке |
| Равноправие режимов | Любое состояние агента редактируется вручную; эквивалентное ручное действие доступно агенту |
| Контекст модели | Канонический view, фактический viewport, раскрытые группы и выделение; не вся таблица |
| Конкурентность | Каждое сохранение использует `expectedRevision`; более новая правка не теряется |

## 4. Контракт данных

### 4.1. Сохранённое состояние

```ts
type FilterCondition = {
  id: string;
  kind: "condition";
  negated: boolean;
  field: string;
  operator: FilterOperator;
  value?: FilterValue;
};

type FilterGroup = {
  id: string;
  kind: "group";
  negated: boolean;
  combinator: "and" | "or";
  children: Array<FilterCondition | FilterGroup>;
};

type SortRule = {
  id: string;
  field: string;
  direction: "asc" | "desc";
};

type GroupRule = {
  id: string;
  field: string;
  direction: "asc" | "desc";
  hideEmpty: boolean;
};

type ReportViewV5 = {
  schemaVersion: 6;
  id: string;
  chatId: string;
  entityType: "animal";
  columns: string[];
  filters: FilterGroup;
  sort: SortRule[];
  groupBy: [] | [GroupRule];
  revision: number;
};
```

Название хранится у чата, а не у `ReportView`. Ферма хранится обычным условием каталога полей внутри `filters`; сервер всегда пересекает результат со списком `farm_access`, поэтому удаление фильтра не расширяет доступ за его пределы.

`FilterValue` — дискриминированное значение: строка, число, логическое значение, дата, относительный период, список или пара границ. Оператор однозначно определяет допустимую форму значения.

### 4.2. Локальное состояние интерфейса

Черновик редактора, открытый popover, загруженные страницы, cursor, viewport, раскрытые группы и выделение не входят в `ReportView`. Они не сохраняются как правила и не передаются агенту до применения.

```ts
type TableContext = {
  viewId: string;
  revision: number;
  viewportRowIds: string[];
  expandedGroupPaths: GroupPath[];
  selectedIds: string[];
};

type GroupPath =
  | []
  | [{ field: string; value: string | number | boolean | null }];
```

### 4.3. Каталог полей

Серверный каталог для каждого поля возвращает ID, название, тип, единицу измерения, допустимые операторы, возможность сортировки и группировки, тип редактора и источник допустимых значений. UI и агент используют один каталог; неизвестное поле или несовместимый оператор отклоняются до запроса данных.

### 4.4. Миграция v1/v2/v3/v4 → v5

При чтении старого представления миграция:

1. преобразует прежние `conditions` в дерево и сохраняет исходное v2-дерево без потери **OR / NOT**;
2. присваивает стабильные ID фильтрам, сортировкам и группировкам;
3. преобразует прежний `farmId` в обычный фильтр **Ферма**;
4. оборачивает плоские v3/v4-фильтры корневой группой **AND**, сохраняет сортировки, а из прежней многоуровневой группировки оставляет внешний уровень;
5. переносит отброшенные поля группировки в обычные колонки, пока число колонок не превышает 30;
6. увеличивает `revision` и записывает v5 один раз, без нового изменения при каждом чтении.

Типы редакторов:

| Тип поля | Значение |
|---|---|
| Текст | строка или список строк |
| Число | число или два числа диапазона |
| Дата | календарная дата, диапазон или относительный период в часовом поясе фермы |
| Логическое | **Да / Нет** |
| Справочник | одиночный или множественный выбор из серверного списка |

Для каждого оператора серверная схема фиксирует обязательность значения, включённость границ `between`, поведение `NULL`, регистр текста и часовой пояс относительных дат.

## 6. Единые операции UI и агента

UI и tools агента вызывают один domain service и одну validation schema. Пользовательские действия выражаются типизированными операциями:

```ts
type ViewOperation =
  | { type: "filter.add"; index: number; condition: FilterCondition }
  | { type: "filter.update"; conditionId: string; condition: FilterCondition }
  | { type: "filter.remove"; conditionId: string }
  | { type: "sort.add"; index: number; rule: SortRule }
  | { type: "sort.update"; ruleId: string; rule: SortRule }
  | { type: "sort.remove"; ruleId: string }
  | { type: "sort.move"; ruleId: string; index: number }
  | { type: "group.add"; index: 0; rule: GroupRule }
  | { type: "group.update"; ruleId: string; rule: GroupRule }
  | { type: "group.remove"; ruleId: string }
  | {
      type: "view.update";
      patch: { columns?: string[] };
    };
```

| ID | Обязательное поведение |
|---|---|
| AG-01 | Агент читает сохранённый view через `getViewState`; DOM и подписи интерфейса не являются источником состояния. |
| AG-02 | UI и агент используют одинаковые операции по стабильным ID. |
| AG-03 | Изменение агента потоково обновляет те же чипы и редакторы без перезагрузки. |
| AG-04 | Следующий запрос агента содержит последнюю сохранённую revision и `TableContext`; неприменённый черновик отсутствует. |
| AG-05 | При `409 VIEW_REVISION_CONFLICT` сервер возвращает актуальный view. Независимая операция повторяется поверх него; несовместимая не применяется молча. |
| AG-06 | Любое состояние агента полностью отображается и редактируется вручную. |
| AG-07 | Эквивалентное намерение через UI и агента создаёт семантически одинаковый список условий и одинаковую выборку. |
| AG-08 | Модель получает только разрешённые tools; `userId`, непроверенный `farmId` и SQL не принимаются от модели. |

## 7. API и сервер

| ID | Обязательное поведение |
|---|---|
| API-01 | View API после каждой мутации возвращает канонический `ReportViewV4` и новую revision. |
| API-02 | Mutation API требует `expectedRevision`, атомарно применяет batch и поддерживает add/update/remove для filter и add/update/remove/move для sort и group по ID. |
| API-03 | Ошибка валидации возвращает стабильный код и путь конкретного узла; невалидный view не записывается. |
| API-04 | Query API применяет фильтр и сортировку ко всей доступной выборке и возвращает revision, snapshot, строки, `nextCursor` и признак конца. |
| API-05 | Group query принимает view, group path и cursor и возвращает либо уникальные group nodes, либо страницу строк из того же snapshot. |
| API-06 | Cursor другой revision или другого порядка отклоняется стабильной ошибкой. |
| API-07 | Каждый запрос повторно проверяет владельца view, `farm_access`, RLS и allowlist полей; значения параметризованы. |
| API-08 | Серверный тайм-аут выборки — 5 секунд; ответ не раскрывает SQL, DSN и внутренний stack. |

## 9. Производительность

1. Проверочный набор — 6 ферм × 8 500 животных, всего 51 000.
2. `farm:benchmark` выполняет 5 прогревочных и 40 измеряемых последовательных запросов.
3. p95 прямого SQL `count + первая страница` после прогрева — не более 1 000 мс; превышение завершает benchmark с ошибкой.
4. Первый экран не ждёт загрузки всей фермы; полный результат не попадает в браузер, tool-result или контекст модели.
5. SLA браузерного render и interaction задаётся только после отдельного измерения: Playwright timeout не считается UX-порогом.

## 10. Приёмка

| ID | Сценарий | Критерий |
|---|---|---|
| T-01 | Пустая панель и простой фильтр | **Фильтр** только открывает пустую вторую строку; **Добавить фильтр** открывает редактор с закрытым выбором поля; условие создаётся за `поле → оператор → значение`, пустой draft не влияет на view. |
