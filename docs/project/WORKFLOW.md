# Разработка и публикация

## Среды

| Среда | Назначение | Когда меняется |
|---|---|---|
| Dev — локальный стенд | Разработка и проверка изменений, локальные БД | По команде на доработку |
| Публичный Git | Код и документация: [arka-agent](https://github.com/s-seleznev/arka-agent), ветка `main` | По команде «коммит / пуш» |
| Live — Vercel | Версия для клиента: [прототип](https://arka-agent-demo-2026.vercel.app/) и [аналитика под паролем](https://arka-usage-report.vercel.app/) | Только по отдельной команде «публикуй / деплой на Vercel / обнови live» |

Dev здесь означает локальную разработку. Отдельный облачный dev-стенд и ветка `dev` не настроены. `main` может быть новее опубликованной версии — push не равен релизу.

## Порядок работы

1. Выполнить задачу локально. Не менять облачные БД, модель, секреты и клиентскую версию ради проверки dev.
2. Проверить изменённый сценарий соразмерно задаче. Для мелких UI-правок действует режим из `AGENTS.md`: без дополнительных проверок и публикации по умолчанию.
3. По команде на push проверить `git status`, обновить сведения об `origin/main` и проверить расхождение. Если ветки разошлись — сообщить до изменений, не делать force push по умолчанию.
4. Перед коммитом проверить состав изменений и запустить `python3 scripts/check-distribution.py`. Обновить затронутые документы и devlog по запросу. Отправить коммит в публичный `origin/main`, проверить удалённый SHA.
5. Только по отдельной команде на live: проверить сборку, секреты и подключения нужной среды; опубликовать нужный проект Vercel; дождаться READY и проверить именно клиентский адрес и изменённый сценарий. Записать deployment и ограничения проверки в devlog.

Команды «сделай», «почини», «обнови доки» и «пуш» сами по себе не разрешают деплой. Миграции, сбросы и перезаполнение облачной БД не выполнять автоматически при работе с локальными данными. Ранее данное разрешение на конкретный релиз не переносится на следующие релизы.

## Границы доступа

`origin` — публичный репозиторий. `private-source` и отдельный архив остаются приватными; обычный push туда не направляется. Аналитика, исходные материалы, секреты, `.local/` и настройки Vercel в публичный Git не входят. Пароль аналитики не записывать в документы и коммиты.

Аналитика публикуется отдельно от приложения, из приватного локального пакета. Обновление прототипа не должно менять аналитический сайт и наоборот. Перед публикацией аналитики обновить её пакет, проверить пароль на странице и прямых JSON/CSV-ссылках; не оставлять открытых старых deployment URL.

На 06.09.2026 у проекта Vercel с приложением нет Git-привязки. Автоматический production-деплой при push не настроен; не подключать его без отдельной команды.
