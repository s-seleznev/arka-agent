# Реализация правил CSV: фактическое состояние

> Протокол этапа реализации CSV. Числа покрытия и результаты тестов ниже относятся к сохранённым отчётам этого этапа, а не к новому прогону текущего кода. Последующие проверки выявляли девять TS2322 в прототипных screens; раннее «TypeScript без ошибок» не описывает нынешний checkout. [Актуальная навигация](../docs/project/README.md).


Основная цепочка «найти правило → выполнить на БД → открыть таблицу → продолжить вручную» работает. Полный план R00–R21 ещё не закрыт: 882 из 6 735 определений прошли компиляцию и SQL-проверку, остальные 5 853 имеют явные причины блокировки. Это не полная независимая проверка исходного смысла всех правил. Это не только недостатки исходника: карта оставшейся реализации и сопоставлений находится в [remaining-gaps.md](remaining-gaps.md).

## Что можно использовать

- Каталог всех исходных списков в продуктовой БД, неизменяемые версии CSV/parser и явные привязки компаний к тестовым фермам. Два parser snapshot по 6 735 определений; обычный поиск показывает последний, старые ID продолжают открываться.
- Поиск по ID, названию и разговорным формулировкам; англоязычные термины переводятся только для поиска. При нескольких кандидатах агент просит выбрать список.
- Инструменты `searchListRules`, `getListRule`, `applyListRule`, `refreshView` доступны через общий слой AI SDK и существующую авторизацию Codex app-server. Подписка и способ входа не менялись.
- Полное дерево И / ИЛИ / НЕ, точные десятичные значения, ссылки на совместимые поля и относительные даты. Пределы: 128 условий, глубина 8, 64 колонки; группировка таблицы остаётся одноуровневой.
- Применение сначала проверяет правило и выполняет запрос; только после успеха меняет представление с проверкой revision. Неизвестный параметр, недостающий mapping или конфликт не создаёт частично изменённую таблицу.
- `ruleContext` хранит правило, binding, параметры и срез. Ручная правка сохраняет происхождение, ставит `modified=true` и получает новый срез без возврата к исходным фильтрам.
- Смена дня фермы или изменение фактов приводит к обновлению расчётной проекции по запросу. Старые страницы явно отклоняются; повтор загрузки сохраняет ручную настройку.

Рабочий пример: [«Проверка списка 541»](http://localhost:3000/chat/965a73a7-ebe4-498a-9ae2-72cc265ddada). В проверенном срезе — 4 животных, по 2 из каждой ветви правила. Это тестовые факты и явно заданная тестовая привязка, а не восстановленные реальные животные исходной компании.

## Проверки приложения

- Unit: 41/41; интеграционные SQL/access/NULL проверки: 11/11. Два opt-in теста не входят в обычный прогон: dynamic registry отдельно прошёл 1/1; recovery ранее отдельно прошёл 1/1.
- Браузер: ограничения сортировки и группировки, 128 условий, ошибка cursor-страницы и повтор загрузки — 4/4. Отдельно проверены создание фильтра, вложенное ИЛИ и конфликт revision.
- TypeScript — без ошибок. Изолированная production-сборка — успешно, 24 страницы; предупреждение `unpdf` об `import.meta` не блокирует сборку. Сборка не заменяла `.next` работающего стенда.
- Полный поиск нашёл 15 дефектов точных названий; после исправления числовых имён и крайних пробелов повтор 9 504 запросов прошёл. Первые провалы сохранены отдельно.
- Исправлены обнаруженные при приёмке дефекты: серверный `node:crypto` в клиентском модуле, пустая OR-группа в проверке области фермы, неизвестные параметры правила, межферменная привязка динамического поля.
- Финальный refresh старого демочата 541 через UI заблокирован auto-review. Сохранённая успешная LLM-трасса относится к прежнему срезу; её нельзя выдавать за свежую проверку после последующих миграций. Нужна кнопка «Повторить» с разрешением на обновление сохранённого среза.

## Производительность пересчёта

После расширения фактов 017/018 полный пересчёт вышел за 60-секундный runtime timeout. Миграция 019 устранила неудачные планы соединений и размножение широкого контекста на каждое поле; EVENT_DATE/EVENT_VALUE и типизированные значения вычисляются пакетно.

Применённый полный пересчёт: **14,486 с**, тайм-аут остался **60 с**. До применения граничный набор прошёл за 14,656 с; семь полей × 51 000 животных совпали с независимым SQL, пакетный путь — с интерпретатором. Это время полного пересчёта, а не обычного запроса таблицы. После смены среза первый запрос может ожидать пересчёта; прогретые запросы измеряются отдельно в [benchmark.json](benchmark.json).

Полный SQL-аудит policy v2: p50 **103,8 мс**, p95 **128,22 мс**, max **318,6 мс** для связки запрос + сводка. Хеши реализации не менялись во время прогона. [execution-coverage.csv](execution-coverage.csv) связывает все 6 735 исходных записей с импортом, компиляцией, SQL и незакрытыми проверками.

## Воспроизведение

Команды выполняются в корне репозитория, кроме блока приложения. Исходные CSV и основной набор животных не сбрасывать.

```sh
python3 scripts/rules-inventory.py
python3 scripts/test-rules-inventory.py
python3 rules/qa/check_source_boundaries.py
```

В `agent-app/`:

```sh
node --import tsx --test tests/unit/*.test.ts
node --conditions=react-server --import tsx --test tests/integration/*.test.ts
node --conditions=react-server --import tsx scripts/rules-import.ts --write
node --conditions=react-server --import tsx scripts/rules-import-verification.ts --verify-idempotency
node --conditions=react-server --import tsx scripts/rules-query-audit.ts
node --conditions=react-server --import tsx scripts/rules-apply-smoke.ts
node --conditions=react-server --import tsx scripts/rules-search-audit.ts
node --conditions=react-server --import tsx scripts/rules-benchmark.ts
```

Recovery integration opt-in требует явно указанных отдельных QA-чатов; пропущенный opt-in тест не считать выполненным. Скрипт apply-smoke создаёт и удаляет только собственный тестовый чат. Источники и generated artifacts конфиденциальны; публикация разрешена только в существующий приватный backup-репозиторий.
