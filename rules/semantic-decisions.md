# Семантика экспорта правил

Все 6 735 записей учтены; синтаксический разбор не подтверждает исполнимость. Источник сохранён в [normalized.jsonl](normalized.jsonl), исходные 18 ячеек — в `raw`. Проверенные количества и SHA-256 — в [source-manifest.json](source-manifest.json).

## Воспроизведение

```bash
python3 scripts/rules-inventory.py
python3 scripts/test-rules-inventory.py
```

Генератор не читает и не изменяет БД. Повторный запуск создаёт побайтово одинаковые артефакты. `rowNumber` — номер записи CSV без заголовка, начиная с 1; это не физическая строка файла. Смещения `span.start/end` — индексы Unicode code points исходной декодированной ячейки CSV; конец исключён. Реальные и записанные как `\n` переводы строк имеют одинаковую структуру дерева, но исходные смещения различаются и сохраняются.

## Что доказано

- Все исходные фильтры представлены узлами: 21 517 сравнений; число маркеров `•` и `filters_count` совпадает у каждой записи.
- Максимум: 119 сравнений, глубина дерева 6, 43 лексических колонки, 1 измерение группировки, 36 корней.
- 6 702 записей прошли синтаксические проверки. 33 записи имеют диагностику синтаксиса/целостности экспорта.
- 24 записи имеют расхождение числа колонок: запятая с пробелом может находиться внутри названия. Полученные части отмечены `lexicalStatus=candidate`. Карта полей содержит кандидатов; 8 006 пар «компания + лексическая подпись» и 2 569 точные подписи нельзя считать подтверждёнными полями реестра.
- Группы `AND/OR` и названия сохраняются. `NOT` поддержан контрольными примерами; в данном снимке оператор не обнаружен.
- Десятичные числа, включая `0E-16`, хранятся строкой без перехода в двоичное число. ISO-дата распознаётся только при календарной валидности. Относительная дата распознаётся только как `Сегодня` или `Сегодня +/- N дней`.

## Исправление парсера v2

75 неоднозначных лексических разбиений v1 восстановлены по сбалансированным скобкам, точным названиям полей из фильтров той же компании и единственному разбиению на объявленное число колонок. Ни похожие подписи, ни поля другой компании не используются. Исходные ячейки и их смещения сохранены. `Возраст (Год, Месяц)` у 13/5533 — одна группировка; два измерения были артефактом прежнего разбиения по запятой.

Версия v1 остаётся в продуктовой БД с прежними ID; повторный импорт v2 создаёт отдельный неизменяемый снимок. Исправление разбора не разрешает неизвестное значение полей.

## Открытые решения

Точные затронутые company/list ID и все исходные фрагменты находятся в [semantic-issues.json](semantic-issues.json); отдельная запись каждого поля и каждого его употребления — в [field-mapping.csv](field-mapping.csv). Один общий неподтверждённый статус не заменяет эти ссылки.

|---|---:|---|---|
| ROOT_COMBINATION_UNCONFIRMED | 4 186 | Правило объединения нескольких корней, в том числе обычных плоских фильтров | Исходный сериализатор/структурный экспорт; решение отдельно фиксируется в версии binding |
| NAMED_BLOCK_MEMBERSHIP_UNCONFIRMED | 768 | Условия членства в сегментах, пересечения, уникальный count и представление | Исходная система на примере company 17/list 3785 |
| OPERAND_KIND_UNCONFIRMED | 3 234 | Строковый литерал, ссылка на поле или параметр; тип и обязательность параметра | Исходные ID и тип правого операнда; название не является доказательством |
| NULL_POLICY_UNCONFIRMED | 930 | NULL, пустая строка и отсутствие события; отрицательные сравнения | Таблица истинности исходного движка на контрольных фактах |

`Сегодня - 365`, `Сего-365`, `DATE_MINUS_DAYS_0`, `Дата С`, `Номер группы` остаются неразрешёнными. Похожие названия не доказывают одинаковые формулы. Неизвестная методика прогноза 305M может быть внешним тестовым входом `SIMULATION`, но этим нельзя разрешить неоднозначность условия.

Отдельно требуют подтверждения день начала схемы пресинхронизации и границы текущей лактации для n-го осеменения. Company 20/list 541 сохраняет обе ветки OR и числа 36/42/48; company 3/list 197 не подменяется вторым событием с конца за всю жизнь.

Противоречия пока не классифицируются: доказательство требует типов полей, правила корней и NULL. Массивы/диапазоны значений не выдумываются из пунктуации правой части. Исполнение SQL, соответствие значений, отображение и реальная LLM в данном реестре не отмечены проверенными; `imported=unverified` означает, что инвентаризация не проверяет состояние продуктовой БД; результаты реального импорта фиксируются отдельно в `import-verification.json`, а `source_inventoried=true` — наличие записи в машинном инвентаре.


## Явный адаптер пустых колонок (binding v2)

`emptyColumnsPolicy=mandatory_identity_if_source_empty` добавляет обязательный номер животного (`primaryIdentifier`) только когда исходный `column_names` пуст, `columns_count=0` и нормализованный список колонок пуст. Это поле идентификации строки интерфейса, не восстановленная исходная колонка; raw и source spans остаются неизменными. Политика записана в `synthetic-policy/v2` и provenance binding. Неизвестные, неоднозначные и повторные исходные колонки по-прежнему блокируют применение; 154 mapping-empty случая не получают fallback.

Прежние определения и bindings v1 не переписываются. Поиск по умолчанию выбирает последнюю явную `synthetic-policy/vN` для каждой фермы; сохранённый binding ID или явно запрошенная версия продолжают обращаться к старой версии. Для неизвестных семейств версий порядок не угадывается.
