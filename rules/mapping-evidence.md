## Политики исполнения стенда

`vitalityPolicy=life_state`: «Живые» → LIFE_STATE=ACTIVE, «Мёртвые» → DEAD, «Все» → без дополнительного предиката жизни. ACTIVE означает активное животное на ферме; SOLD и CULLED остаются отдельными состояниями. Это явная синтетическая политика, а не подтверждение исходного смысла «Живые». Поля isExited/isArchived не используются вместо LIFE_STATE.

`rootPolicy=flat_and` соединяет AND только несколько неназванных предикатов. Несколько именованных корней остаются заблокированными. `nullPolicy=sql_null` и `emptySelectionPolicy=no_predicate` — явные правила стенда, не восстановленные по названию поля.

Компилятор перед возвратом patch вызывает [validateReportViewState](../agent-app/lib/farm/view-model.ts), который проверяет типы, единицы сравнений полей, доступность операторов, уникальность ID, глубину/число условий, колонки и группировку. Проверка выполняется над временным объектом в памяти и не создаёт представление в БД. Привязка к разрешённой ферме остаётся отдельным серверным требованием.

11 тестов [rule-compiler.test.ts](../agent-app/tests/unit/rule-compiler.test.ts) включают отрицательные примеры близких, но разных полей, запрет сравнения с farmId, предел глубины и ACTIVE/DEAD. [compiler-coverage.csv](compiler-coverage.csv) содержит результат для каждого исходного ID; [compiler-audit.json](compiler-audit.json) хранит контрольные суммы реестра и нормализованного источника.


## Динамические bindings v2: существующие типизированные факты

Точные подписи перечислены в [demo-bindings.json](demo-bindings.json), а не добавлены через нечёткий поиск. Основания — типы событий и поля деталей в миграциях [017](../db/migrations/017_additional_rule_facts.sql) и [018](../db/migrations/018_additional_rule_dates.sql). Все значения выбираются из эффективных событий на asOf; даты учитывают часовой пояс фермы.

| Поле реестра | Смысл и граница |
|---|---|
| BIRTH_WEIGHT_KG | Вес при рождении, BORN.birth_weight_kg, кг |
| EXIT_DATE / EXIT_REASON | Дата и причина последнего эффективного EXITED; причина — поле причины, не комментарий |
| LAST_MILK_TEST_KG | milk_kg последнего MILK_TESTED; не последнее суточное молоко |
| FIRST / THIRD_INSEMINATION_DATE_CURRENT_LACTATION | 1-е / 3-е осеменение внутри текущей лактации; без CALVED — NULL, не пожизненная нумерация |
| LAST / PREVIOUS_WEIGHT_DATE | Последнее / предпоследнее MEASURED с видом WEIGHT; не дата произвольного измерения |
| CURRENT_LACTATION_START_DATE | Дата начала текущей лактации по последнему CALVED; не произвольная или предыдущая лактация |
| LAST_CALVING_DIFFICULTY | Поле реестра доступно, но подпись «Тяжесть отела» не доказывает область последнего отёла: CSV binding не добавлен |

Миграции 017/018 добавляют 10 определений: 9 используются явными CSV bindings, LAST_CALVING_DIFFICULTY остаётся без такого binding. Политика обязательного номера для действительно нулевых колонок описана в [semantic-decisions.md](semantic-decisions.md).

Нулевая лактация не подменяется текущей: подписи «Дата 1 осеменения 0 лактации», а также осеменение тёлки требуют отдельного подтверждённого диапазона событий.

Подписи «Дата осеменения», «Вес», «Дата 1 ИО» и «Дата 3-го осеменения» без временной области не сопоставлены. Количества событий не выводятся из дат. Повторные исходные колонки не схлопываются.
