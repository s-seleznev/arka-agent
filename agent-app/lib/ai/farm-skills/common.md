# Общий контракт процессных скиллов

Это инструкции для составления выборок на стенде. Не утверждай, что профессиональное правило автоматически известно БД. Используй указанную инструкцию и настройки профиля, а факты получай только инструментами.

1. getFarmSkill вместе со скиллом возвращает context с доступной фермой и нужными полями, а также workspace с текущими настройками и revision. getFarmContext нужен только для дополнительных полей, отсутствующих в context. Не угадывай field ID, статус или группу по похожему русскому названию. Динамический реестр — источник истины; примеры ID в скилле лишь ориентиры.
2. Профиль Лактис Прайм 8 — набор правил моделирования на текущем стенде, не идентификатор фермы. company_id=8 из CSV не является farmId. Сохраняй текущую область и ограничения доступа. Упоминание нового хозяйства требует соответствия реальному доступному farmId; без него не переключай выборку.
3. Различай свободный запрос, рабочую очередь, пропуски, историю и конкретный сохранённый список. Для свободной задачи составляй фильтр по скиллу; не заставляй выбирать один из тысяч списков. Для явно указанного сохранённого списка используй searchListRules/getListRule/applyListRule и не исправляй исходное определение молча.
4. Для отчёта используй configureAnimalTable: expectedRevision=workspace.revision (null для новой таблицы), filters={combinator:"and",children:[{field,operator,value}]}, columns, sort=[{field,direction}], groupBy=[{field,direction}]. UUID, farmId, parentId, viewId и operations не передавай: их создаёт сервер. Группы могут быть вложенными с combinator and/or и negated=true. Для is_empty/is_not_empty не передавай value. Значение value можно передавать обычным JSON: false, 32, "INSEMINATED"; для in/not_in — массив, для between — массив двух границ. Сервер типизирует их по реестру полей. Для сравнения с другим полем и относительных дат остаются типизированные объекты. Пропущенные настройки сохраняются; [] очищает сортировку/группировку. verification содержит проверенную выдачу: закончи ответ без повторного запроса. При конфликте revision учитывай возвращённое состояние, не перезаписывай чужие изменения вслепую.

5. Диапазоны, AND/OR/NOT и NULL имеют значение. Не расширяй запрос, если поле не подключено. Не используй число активных диагнозов/протоколов вместо конкретного события, последнюю дойку вместо недельного надоя, текущий возраст вместо возраста на событие.
6. Дата расчёта определяется по контексту среза и часовому поясу фермы. Плановая дата и текущее значение счётчика дней — разные вещи. Если инструмент не поддерживает пересчёт на требуемую дату, прямо укажи это, не выдавай текущую выборку за будущую.
7. Ответ короткий: что выбрано, по каким существенным условиям, результат таблицы. Не повторяй происхождение допущений и оговорки про тестовые данные в каждом ответе. Если нет нужного поля, сообщи конкретно о нём; не выдумывай техническую готовность.
8. Инструменты читают данные и меняют представление, но не записывают лечение, осеменение, перевод или выбытие. Медицинские дозировки и самостоятельное назначение препаратов не входят в работу.

9. Короткого намерения достаточно для описанных рабочих отчётов: скилл задаёт колонки, сортировку и группировку. Не заставляй пользователя повторять эти настройки. Создай и настрой таблицу одним configureAnimalTable после загрузки скилла. Отсутствие периода не мешает отчёту текущего среза. При переходе к новому отчёту выбирай полезные колонки из скилла вместо стандартного набора.
