Восемь инструкций подключены через getFarmSkill в общем createFarmTools. Codex app-server и AI SDK получают один и тот же инструмент. Системный промпт содержит только индекс; полный текст загружается по выбранному ID.

Общие инструкции: common.md. Настройки и происхождение решений стенда: profile.json. Реальный справочник полей возвращает getFarmContext; словарь не дублируется в скиллах. Профиль не меняет данные БД и не создаёт отсутствующие поля.

## Изменение и доставка

Редактировать content/*/SKILL.md, common.md, profile.json и manifest.json. При изменении принятого поведения повышать соответствующую версию. Из agent-app выполнить `npm run skills:build`; `npm run skills:check` проверяет синхронность. predev/prebuild также собирают bundle.json. Статический JSON включается в сборку приложения; runtime не читает произвольные пути и не зависит от рабочей директории для скиллов.

## Область профиля

FARM_SKILL_PROFILE_ID=lactis-prime-8 и FARM_SKILL_PROFILE_FARM_IDS со списком UUID явно включают профиль. Без них инструмент отказывает. Все доступные пользователю фермы должны входить в этот список; смешанная область с иной фермой также отклоняется. Это намеренно строгая первая реализация, а не универсальный выбор профиля по каждой ферме. Для другого хозяйства нужна отдельная конфигурация/профиль, не автоматическое наследование Lactis.

В БД остаются шесть ферм; серверный FARM_ACTIVE_ID ограничивает текущий стенд одной фермой «Лактис Прайм 8». Исходный company_id=8 не заменяет их UUID. Изменение профиля не выдаёт доступов. .env.local не публикуется и сохраняется между перезапусками. Авторизация Codex не менялась.

Сценарий проверки: scripts/farm-skills-smoke.ts. --configure-local-profile — отдельное изменение локального профиля для доступных ферм; --verify-recorded — независимая SQL-сверка сохранённого результата. Обычный запуск использует существующую авторизацию, создаёт только временный чат/вид и очищает их. Протокол: analysis/lactis-prime-8/skill-smoke.json в корне проекта.

Неподключённые атрибуты этапов вакцинации, конкретных протоколов или истории не заменяются приближёнными полями. В таких случаях агент называет конкретное отсутствующее поле; готовность инструкций не означает готовность всех необходимых данных. Следующий этап при необходимости — подключение этих фактов БД.
