# Режим быстрых UI-правок

Во время визуального ревью мелкую атомарную правку интерфейса выполнять сразу и только в запрошенном месте. Результат должен появиться на уже запущенном стенде через hot reload.

После такой правки не запускать тесты, линтер, TypeScript, сборку, миграции, аудит, рефакторинг, обновление документации, commit или push. Пользователь сам проверяет результат на экране.

Полную приёмку выполнять только по отдельной прямой команде пользователя.

## Dev, публичный Git и live

По умолчанию работать только локально. Команда на push означает отправку кода в публичный `origin`, но не деплой. Публикация на Vercel допускается только по отдельной явной команде для текущего релиза. Не менять облачные БД и секреты в рамках dev-проверок. Не включать автоматический production-деплой без команды.

Перед push проверять состав Git: `python3 scripts/check-distribution.py`. Аналитика, исходники клиента, ключи и локальные конфигурации не должны попадать в публичный репозиторий. Порядок работы: [WORKFLOW.md](docs/project/WORKFLOW.md).
